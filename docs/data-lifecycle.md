# Data lifecycle: what Talon deletes on its own

Everything Talon removes without being asked at that moment: retention
windows, caps, sweeps and cleanup on failure. If something went missing,
check here first. Paths are relative to the Talon home (`~/.talon`) unless
noted.

"Recoverable" means you can get the data back after Talon deleted it. Most
of it comes back from a snapshot (docs/backups.md). A snapshot only helps
while it exists itself, so the backup retention row matters for every other
row.

## Only when you ask

These never happen on their own. They are listed because they are the
other ways data leaves Talon.

| What                                                 | Trigger                                                                                                                         | Recoverable?                                                                                                                    |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| A chat's history                                     | `talon history purge <chatId>` (asks you to type the chat id, or `--yes`)                                                       | Only from a snapshot. Take a checkpoint first (the command says how).                                                           |
| A chat's session mapping                             | `/reset`, a backend switch, a pinned backend that is no longer enabled at boot, a definite "session not found" from the backend | Yes: the old id is archived (`sessions.archive`) and the transcript stays on disk. History is kept.                             |
| Files created after a snapshot                       | `talon backup restore <id>`                                                                                                     | Yes: the pinned `pre-restore <id>` checkpoint taken first holds them.                                                           |
| Skills, scripts, plugins, cron jobs, goals, triggers | Their delete commands and tools                                                                                                 | From a snapshot                                                                                                                 |
| A native chat                                        | Deleting it in the app                                                                                                          | The session mapping is dropped; history rows are kept and the chat is flagged hidden (only `talon history purge` deletes rows). |

## What never deletes

- Resets, backend switches, model reconciles at boot and native chat
  deletion never delete chat history. History rows are only removed by
  `talon history purge` (see docs/chat-history.md).
- A transient error from an OpenCode or Kilo server (connection refused
  while it starts, a 5xx, a timeout) never drops the chat's session. Only a
  definite not-found does, and the old id is archived.
- Retention never prunes a pinned snapshot, the newest snapshot that passed
  verification, or a remote snapshot whose manifest cannot be read.
